# Project knowledge

1. Работать с историей только на чтение; исключать credentials, токены, `.env`, бинарные вложения и внутреннее состояние приложения.
2. Сначала построить инвентарь: ID, дата, проект, тема, ценность, открытый вопрос и источник доказательства.
3. Группировать по устойчивому рабочему результату, а не по случайному названию чата. Низкоуверенные записи помечать как требующие проверки.
4. Для handoff собрать цель, контекст, ограничения, уже сделанное, точные пути, команды, тесты, артефакты и следующий шаг.
5. Не считать наличие результата в истории доказательством актуальности: повторно проверить файл, remote, тест или внешний статус.
6. Публиковать только обезличенные и лицензируемые материалы; секреты и корпоративные данные никогда не включать в репозиторий.

## Пример

Для переноса видеопроекта: `brief.md`, `script.md`, `storyboard.md`, `asset-manifest.md`, `build.md`, `checksums.txt`, `known-limitations.md`. Получатель должен собрать или проверить результат без чтения исходного чата.
