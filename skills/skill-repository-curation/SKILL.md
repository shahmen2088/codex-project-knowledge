# Skill repository curation

1. Define the user's recurring task groups and acceptance criteria.
2. Prefer official or actively maintained sources; inspect the actual skill and license, not only repository popularity.
3. Reject missing licenses, opaque installers, secret-handling risks, unsupported tool assumptions, and broad auto-trigger descriptions.
4. Score candidates on task fit, evidence, maintenance, portability, token cost, verification, and safety.
5. Avoid vendoring when a maintained upstream package can be linked or installed directly.
6. Record provenance, version or commit, license, adoption decision, and review date.
